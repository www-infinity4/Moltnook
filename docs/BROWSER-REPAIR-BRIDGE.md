The Infinity public browser observer saves `public-live-browser.json` and screenshot directories in `infinity-live-browser-observations`. On an observation-job failure, the failure-analysis job validates the report, clones allowlisted public source at an immutable SHA, and locates simple ID, class, or exact attribute selectors in static markup. Ambiguous matches and dynamic templates need a repository-specific parser; no automatic textual replacement is performed.

The handler saves deduplicated `[Agent Job]` issues to the existing Oracle-Octaves intake using the existing GHP secret with issue write permission there. Missing permission produces a blocked result. This is a durable repair ticket, not confirmation that the brain executor claimed it: receipts explicitly set `executorQueued:false`. The existing cross-repository engine still needs an authenticated intake-to-claim adapter for these tickets. The interactive GitHub connection does not supply credentials to Actions.

Expected href values come from observer source facts, never from the actual broken href. Screenshot paths reference the workflow artifact linked by run URL. The public observer does not verify wallet transactions, authenticated controls, deployment of the checked-out commit, or every button on every site. Page failures without a selector remain page-inspection jobs. Closed matching tickets are retained as existing evidence rather than treated as proof of repair.

Run focused checks: `node --test scripts/automated-repair-handler.test.mjs agents/repository-engine/browser-observation-gate.test.mjs`. Invoke the hook with `node scripts/automated-repair-handler.mjs artifacts`. For a local source lookup, pass a source directory and set SOURCE_REPOSITORY to its matching owner/repository. The bridge does not edit code or wallet data. Its job instructions require a targeted pull request, tests, and fresh browser evidence before completion.
